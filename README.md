# Keeliom

- **Status:** v0.5.0
- **Version:** 0.5.0
- **Date:** 2026-11-26
- **Location:** standalone repository.
- **Name:** Keeliom — Keel (stability) + Axiom (foundational truths).

## Idea

Keeliom is Markdown files, skills and conventions. There is no CLI, runtime or
environment. An LLM or a human reads the files and works from them.

Each fact has one home. The plugin holds the rules. A project holds its specs.
A feature is split by reader: `feature.md` for people, `spec.md` for agents.

## Flow v0.5

1. Run `setup` to write `app.md` and the Keeliom block.
2. The product owner writes `brief.md`, a ticket or a plan.
3. Run `feature`. It writes `feature.md` first, asks only about missing
   decisions, then derives `spec.md`.
4. A requirement or a decision change adds a change entry. A wording fix does
   not.
5. Run `keeliom:check`. It prints findings and writes `STATUS.md`.
6. A developer reads `feature.md`. An agent reads `app.md`, `feature.md` and
   `spec.md`.
7. When the feature ships and `check` passes, set `Status: done`.

## Project structure

```
<project>/
  app.md
  STATUS.md
  CLAUDE.md
  AGENTS.md
  changes/
  plans/
  features/
    F0001-add-book/
      brief.md
      feature.md
      spec.md
      changes/
        0001-initial.md
```

`brief.md` and `plans/` are optional. The project does not copy the Keeliom
repository. The plugin provides the rules, the skills and the templates.

## Files

- `app.md` — the project. Header: `Keeliom`, `Status`, `Language`.
- `feature.md` — for people: `Overview`, `Description`, `Out of scope`,
  `Decisions`, `Open questions`.
- `spec.md` — for agents: `Rules` with stable `R<n>` IDs, then optional `Data`,
  `API`, `Screens`, `Tasks`.
- `changes/` — append-only history with five fields: `Date`, `Reason`,
  `Changed`, `Decisions`, `Source`.
- `STATUS.md` — generated by `check`. Never edit it by hand.
- `plans/` — free-form documents that span features.

The formats live in the plugin's
[`RULES.md`](plugins/keeliom/rules/RULES.md). The checks live in
[`CHECK.md`](plugins/keeliom/rules/CHECK.md).

## Principles

1. **Brief first.** Start from a short description or a ticket.
2. **Convention over configuration.** Fixed file names and sections.
3. **One directory per feature.**
4. **One home per fact.** A rule is written once and cited elsewhere.
5. **The LLM does not invent.** It asks only about missing decisions.
6. **History records why.** Spec maintenance stays in the commit message.
7. **Zero dependencies.** Markdown only.
8. **Append-only history.** Old change entries are never edited.

## Plugin

Keeliom is a Claude Code plugin marketplace:

```text
/plugin marketplace add khrvi/keeliom
/plugin install keeliom@keeliom
```

The plugin bundles four skills:

- `setup` — set up a new or existing project, or import features from code.
- `feature` — create or change one feature from a brief or ticket, or generate
  every required feature from a plan.
- `check` — run the checks and write `STATUS.md`.
- `migrate` — migrate a 0.2.x or 0.3 project to 0.5.

Skills live in `plugins/keeliom/skills/`, rules in `plugins/keeliom/rules/`,
templates in `plugins/keeliom/templates/`. For local development, run these
from the directory that contains `keeliom/`, or pass the absolute path:

```bash
claude plugin marketplace add ./keeliom
claude plugin install keeliom@keeliom
```

## Distribution

The plugin is the default. The project receives only generated files. See
[03 — Distribution](docs/03-distribution.md).

For non-Claude Code environments, the repository is plain Markdown: point the
LLM at it or copy the plugin's `rules/`, `skills/` and `templates/`.

## Roadmap

- **v0.1** — first release.
- **v0.2** — system contracts in `app.md`, decisions and sources, 37 checks,
  fixtures, a project review skill.
- **v0.2.1** — a migration skill for existing projects.
- **v0.2.2** — `Release` and `Repositories` headers, multi-repo features,
  one Decisions/Open questions grammar, one Source grammar, a safe upgrade.
- **v0.2.3** — scoped M16, wider S5 and S7, C1 additions, API and Data model
  details, a project change log, `TODO.md`, a fixture runner.
- **v0.3** — one rule set, `Reads`, Decisions `Status`, `TBD` as the only
  placeholder, 36 checks.
- **v0.4** — one file per reader: `feature.md` and `spec.md`. Rules live in the
  plugin. Slim change entries. 9 checks and 4 skills.
- **v0.5** — whole-plan generation, capability ownership, deeper spec checks
  and visible warnings.
